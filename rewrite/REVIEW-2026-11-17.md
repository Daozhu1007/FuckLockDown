## 结论

**当前不能按“重写 LockDown Browser，并删除检测其他程序后要求关闭的功能”验收。**

确实存在逆向分析和针对性补丁工作，但目前交付的是依赖指定原版的内存补丁启动器。它不能独立提供浏览器功能；本机安装的原版与它预期的路径、版本、架构均不一致；正式构建也没有包含报告中成功运行的延迟补丁流程。现有测试没有建立目标功能的有效原版/修改版对照。

本审查将用户当前请求作为要求，将 GLM 报告、仓库文档及日志作为待核实材料；不把其中对历史要求或“成功”的描述自动视为事实。

## 严重问题：A/B 测试没有证明 ProcessCloseDlg 功能被删除

最后一次完整 [对比回执](D:/Code/FuckLockDown/rewrite/lab/reports/reply-1794824072969784700-eaa68936.json) 的实际内容是：

| 观察 | 原版基线 | 实验版 delayed |
|---|---|---|
| 采样数 | 90 次，脚本每 0.5 秒采样一次 | 100 次，脚本每 0.5 秒采样一次 |
| 四个改名 cmd 进程 | 每次均为 1,1,1,1，全部存活 | 每次均为 1,1,1,1，全部存活 |
| 主要模态窗口 | VM 检测拒绝框 | Choose Server |
| ProcessCloseDlg 正例 | 没有记录到 | 没有记录到 |
| 补丁事件 | 无 | 15 次 patch_verified |

这些记录可以支持“实验版在该次 VM 运行中进入 Choose Server，四个进程存活，十五处补丁写入并读回”，不能支持“已经证明删除要求关闭程序的功能”：

1. 基线被 VM 对话框挡住，没有成功触发待删除的提示，因而没有有效正例。
2. 四个进程在基线也全部存活，这项指标没有区分修改效果。
3. 实验版到达 Choose Server，不证明随后真正执行了目标进程检测流程；现有记录没有建立该界面与全部目标检测的先后关系。
4. 原版与实验版还相差 VM 字符串改写，两个阶段到达的流程不同，不能据此把差异全部归因于 ProcessCloseDlg 补丁。
5. 对话框枚举实际每四轮执行一次，约每 2 秒记录一次，见 [ComparisonTest2.ps1:104](D:/Code/FuckLockDown/rewrite/lab/guest/ComparisonTest2.ps1:104)，不是每 0.5 秒一次；有限轮询也不能排除短暂弹窗。

测试脚本明确在 [第 124 行](D:/Code/FuckLockDown/rewrite/lab/guest/ComparisonTest2.ps1:124) 调用 ExperimentLauncher.exe --patch-mode delayed，未使用 dist 正式启动器。

因此，报告中“核心目标已达成”“真实机器上原版会在此场景弹框”的表述超过了已保存的行为证据。现有材料也没有证明检查在全生命周期只执行一次，或固定延迟 10 秒在其他机器上必定早于目标提示出现。

## VM 为什么会出现

lab 是隔离运行原版、安装驱动和进行行为观察的测试环境。选择 VM 做隔离测试有合理用途，但它不是用户要求的最终产品，也不是交付启动器的运行依赖。启动器在用户 Windows 上直接寻找并创建原版进程，不会依赖 QEMU 来提供浏览器。

原版的 VM 检测阻挡了实验后，后续大量工作转向了 VM 指标字符串改写。这是测试环境遇到的问题，解决它不等于完成目标功能的删除。

而且“VM 中和仅为实验而设”与正式构建的实际代码不一致：[第 764 行](D:/Code/FuckLockDown/rewrite/src/ProcessPolicyLauncher.cs:764) 的 ResourceNeutralizer.StartWatch 不在测试编译条件内，实际正式二进制也包含该调用。它会尝试扫描、改写包含签名句的私有内存区域，没有“仅当运行在 VM 中才启动”的条件。因此不能断言该代码在真实硬件上不会触发。

## 已确认的有效局部工作

本次独立按 PE RVA 读取项目中提取出的 2.1.6.03 原版，核对了补丁计划：

- 原版 SHA-256 与计划一致。
- 15 处预期原字节全部匹配，替换长度全部相等，共 76 字节。
- 当前 ProcessPolicyLauncher.cs 的哈希与 test-artifacts/build.json 中的构建记录一致。
- 六处核心调用采用不同固定返回值；它们并非报告措辞中的“全部 NOP”。
- 哈希不匹配时拒绝执行的行为，本次在用户本机旧版上得到了验证。

这表明并非没有实际实现；但静态字节正确和内存写入成功不等于目标功能、正常启动和后续流程已经通过验收。

[五项集成测试](D:/Code/FuckLockDown/rewrite/tests/test_launcher.py:1) 使用自建 fixture，主要检查一个返回整数的原生函数、参数转发、哈希拒绝和故障清理。它们不测试原版 ProcessCloseDlg、原版正常启动或实际使用兼容性。本次没有重复运行这些 fixture 测试，因为它们不能解决上述验收缺口。

## 重新验收所需的最低证据

- 明确交付是独立重写程序，还是依赖原版的功能修改启动器；说明支持的精确版本、架构和依赖。
- 在受支持版本和有效配置中，先用同一组触发程序让原版确实出现目标关闭提示，确认正例。
- 用最终交付的同一个二进制和明确哈希复测，证明该提示消失、相关程序继续存活，并继续完成相应正常启动流程。
- 将实验辅助功能与正式行为说明清楚，避免用实验版结果代替正式版验收。
- 对固定延迟的适用性、重复运行稳定性及后续流程，按实测结果描述，不用单次短时存活推导永久成立。
